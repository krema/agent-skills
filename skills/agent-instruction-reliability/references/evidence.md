# Evidence and limits

## Question and coverage

**Question:** When agents using `obra/superpowers` did not follow a relevant instruction, what broke, what was actually changed, and which repair principles transfer to another coding-agent skill?

**Use:** Diagnose and harden skill-driven coding workflows in Codex, Claude Code, and similar hosts. This is not evidence that any prompt can guarantee obedience.

**Search snapshot:** 2026-10-13. I fetched `repos/obra/superpowers/issues?state=all&per_page=100` through GitHub's API, all 24 pages. After excluding pull requests, the snapshot contained **1,013 issues: 192 open, 821 closed**. I screened every title and body with families of terms for ignored/skipped/failed instructions, skill loading, approval gates, TDD, reviews, worktrees, plans, subagents, and context loss. I inspected issue bodies, maintainer comments, cross-references, and the repository's `main` tree at commit [`bb92a777`](https://github.com/obra/superpowers/commit/bb92a77741419a4ab5f06e711a283343f1ada0c3) for decision-critical cases. The [issue index](issue-index.md) records the included direct reports and close comparators. Thematic inclusion requires an observed or plausibly reproduced departure from a relevant instruction, or a proposed fix directly tested against one. Generic installation failures, pure feature requests, and unrelated code defects were excluded.

This is a **repository-wide issue screen**, not a formal systematic review: GitHub reports are heterogeneous, some lack traces, and screening judgments are interpretive. A closed state alone does not establish a fix. The index preserves open, duplicate, unreproduced, platform-limited, and fixed cases separately.

A later [focused comparison](cross-framework.md) examined relevant primary issues and changes in BMAD Method and Compound Engineering Plugin. That comparison is selective; the 1,013-issue count applies only to Superpowers.

## Decision map

| Proposed rule in `SKILL.md` | Support | Basis and applicability | Observable check |
| --- | --- | --- | --- |
| Inspect discovery and actual skill read before editing skill prose | E1–E3 | Engineering inference from distinct activation failures; relevant when a skill appears ignored | Invocation precedes dependent tool calls |
| Record the exact instruction, priority, phase, and authorization scope | E6–E7, E15 | User priority is an authoritative rule in current `using-superpowers`; phase-boundary diagnosis is engineering inference | Downstream work waits at the intended boundary, or proceeds when already authorized |
| Verify child receives binding requirements and a real brief | E8–E9, E16 | Observed handoff failures; host-specific | Inspect child prompt and existence/content of referenced file |
| Require inspectable evidence for an observed completion skip | E4–E5, E10–E12 | Implemented patterns, with cost caution from E13–E14 | Diff, report, reviewer verdict, test output, or plan-bound ledger exists before DONE |
| Treat host limitations and closed-without-fix cases honestly | E2, E11, E15 | Source classification requirement; prevents false repair claims | Reproduction is tied to a supported host/version or limitation is reported |
| Test failure and boundary cases, not only wording | E3, E5, E14–E15 | Trace-based trials and counterexamples; engineering inference | Action trace shows desired sequence and no unintended trigger |
| Distinguish target-skill entry from wrapper failure | E19 | Merged host-specific repair with reported dry runs | Target skill start is observed, or pre-entry unreachability is reported |
| Prevent same-task recursion and verify parent return | E17–E18 | Trial and implemented protocol, each narrow | First child action advances its task; parent resumes its pending step |
| Compare action-time guidance and nested writes with scope | E20–E21 | Merged contradiction check plus unresolved reports | Exact conflicting clauses and diff are inspected, with no unrelated guidance edits |

## Unresolved questions

- No matched, repeated trial establishes that this *new* diagnostic skill improves agent compliance across hosts. Its structural checks and author walkthrough are recorded in [validation](../evals/validation.md).
- Open recent Codex reports [#2372](https://github.com/obra/superpowers/issues/2372) and [#2506](https://github.com/obra/superpowers/issues/2506) show that reading a skill may still fail to preserve an approval or consent boundary. The issue evidence does not isolate model, host, and skill contributions.
- [#2386](https://github.com/obra/superpowers/issues/2386) suggests a trigger description problem, while [#2051](https://github.com/obra/superpowers/issues/2051) reports failure to re-check a second skill during an ongoing workflow. Neither has a verified universal repair.
- The BMAD and Compound cases were selected through focused searches, not complete repository issue screens. Their merged fixes and reported trials support specific diagnostic branches, but cannot establish that this new skill improves instruction-following behavior.
