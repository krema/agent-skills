## Choose the right verification

An obsolete command with a verified replacement needs a fact check and appropriate execution if available. A meaning-preserving consolidation needs an invariant check, including exceptions. A changed route or ambiguous decision benefits from a realistic execution trial because reading the prose cannot establish that the agent will follow it. Claims of higher success, lower cost, or reliable equivalence require a matched comparison and enough trials for the claim.

These are choices based on uncertainty, not document size or a fixed sequence every edit must pass. When a trial cannot run, report exactly which behavior remains untested and avoid exposing essential constraints solely through an unverified route. Do not withhold unrelated verified fixes because another candidate lacks a benchmark.

## Evidence for an individual edit

Record material decisions compactly in the report: **content → action → expected effect → basis → verification**. Group equivalent changes rather than writing one report row per sentence.

- **Verified local fact:** a command, scope, schema, or owner requirement checked against an authoritative artifact. Cite its location. This supports correctness, not an unmeasured speed claim.
- **Observed task evidence:** a reproducible failure or matched before/after outcome. State model/host, task, and what was measured; one success is not general validation.
- **Research-supported hypothesis:** identify applicable E-entries, population differences, and a counterexample that could overturn the decision. A related paper is not evidence that this particular rewrite works.
- **Editorial judgment:** an untested clarity or organization choice. Label it; do not invent scientific support. Meaning-preserving low-impact edits can proceed without an expensive benchmark.

Example: “Replace `npm test` with `pnpm test:unit`: package.json defines only test:unit and the lockfile uses pnpm; expected effect is a runnable unit-test command. Verified against those files; command execution not performed.” This is stronger evidence than citing a prompt-engineering paper for the command choice.

Avoid deleting a binding owner constraint simply because it lacks a paper. Evidence informs implementation; it does not overrule task authority. Avoid treating an agent's self-confidence, an analyzer score, a famous vendor's preference, or an observational correlation as a causal improvement result.
